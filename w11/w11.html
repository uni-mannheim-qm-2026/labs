Generalized linear models

The linear model has been our tool so far. A generalized linear model (GLM) keeps its right-hand side and lets the outcome be something else. Every GLM has three parts:

  • Stochastic component: the distribution of .
  • Systematic component: the linear predictor , exactly what we know from OLS.
  • Response function : maps the linear predictor to the range the distribution’s parameter allows. Its inverse is the link function.

The models of this and next week:

Model Stochastic component Linear predictor Link function Response function
Linear , rnorm()
Logit , rbinom(size = 1) , plogis()
Probit , rbinom(size = 1) , pnorm()
Poisson , rpois() , exp()
Negative Binomial* , rnbinom() , exp()

is the CDF of the standard Normal. Only the stochastic component and the response function change between models. The linear predictor stays the same.

* Strictly speaking, the negative binomial is a GLM only if is known. We estimate it, and sits inside the variance function, unlike in the linear model, which only scales it. See next week.

A binary outcome

Our is 0 or 1. On the side everything is as we know it from OLS: a numeric predictor. We need a model that respects the outcome and uses the predictor. The two tools we already have each do only one of these.

TipThe log-likelihood in the regression table

What it is: the likelihood multiplies the probabilities of all observations at the estimates. logLik is its log, : how probable the model makes the observed data, on the log scale. We’ll compute it ourselves in the next section.

Why we report it: a logit has no in the OLS sense. The log-likelihood is what we compare models with instead, in likelihood ratio tests and in information criteria such as the AIC (next week).

How to read it: on its own the number means little. It is usually negative and grows in size with . Between models of the same outcome on the same data, higher (closer to 0) is better. Models with a different type of distribution aren’t comparable this way, like the OLS and the logit in our table: a Normal gives densities, a Bernoulli probabilities.

Divided by and exponentiated, it gives a rough feel for the fit, the (geometric) mean probability the model gives to each observed vote:

logit_model |>

  mutate(probability_per_vote = exp(as.numeric(logLik) / nobs)) |>
  select(logLik, nobs, probability_per_vote)

Maximum likelihood estimation

How does glm() find ? As in Week 10, it maximizes a likelihood. Each vote is a Bernoulli with its own , and with independent votes the likelihood is a product:

and the log-likelihood a sum:

The same building blocks as last week, plus g() from above: x_beta() for the systematic component, g() for the response function, l() for the stochastic component, and ll() unchanged.

x_beta <- function(theta, left_right, age) {
  pluck(theta, 1) + pluck(theta, 2) * left_right + pluck(theta, 3) * age
}

l <- function(theta, y, left_right, age, log = FALSE) {
  dbinom(y, size = 1, prob = g(x_beta(theta, left_right, age)), log = log)
}

ll <- function(theta, y, left_right, age) {
  sum(l(theta, y, left_right, age, log = TRUE))
}

The response function also takes care of the parameter space: can be any number and still stays between 0 and 1. No exp() trick as for last week.

yes_votes <- nature |>

left_right_values <- nature |>

Model fit

Is this a good model? For binary outcomes we compare the model’s probabilities , the predicted probabilities, with what actually happened. augment() returns them with type.predict = "response".

Classification table

A cutoff of 0.5 turns each predicted probability into a classified vote:

classified <- logit_model |>
  augment(type.predict = "response") |>
  mutate(classified = if_else(.fitted > 0.5, 1, 0))

classified |>
  count(yes, classified) |>
  pivot_wider(names_from = classified, values_from = n, names_prefix = "classified_")

    yes classified_0 classified_1

The percent correctly predicted (PCP) is the share on the diagonal. It only means something next to a naive benchmark, the percent in the modal category (PMC): always guess the more common vote.

fit_summary <- classified |>
  summarize(
    pcp = mean(yes == classified),
    pmc = max(mean(yes), 1 - mean(yes))
  )
fit_summary
# A tibble: 1 × 2
    pcp   pmc
  <dbl> <dbl>
1 0.922 0.543

The model gets 92% right, against 54% for always guessing “yes”. On a close vote, the benchmark is low and the improvement real. On a lopsided vote, where 98% of MEPs vote yes, the PMC is 98%, and a model can match that without predicting a single no.

Precision, recall and F1

Machine learning reads the same table from the side of one class, here the yes votes, the “positives”. The same measures go by several names. With the number of MEPs with observed vote and classified vote :

Measure Also called Formula Used for
Accuracy PCP overall share right; compare with the PMC
Precision positive predictive value when false alarms are costly: how many predicted yes votes are real
Recall sensitivity, true positive rate, hit rate when misses are costly: how many actual yes votes are found
Specificity true negative rate recall for the no votes; with recall, the axes of an ROC curve
F1 F-score one number for rare events, high only if precision and recall both are 
classified |>
  summarize(
    accuracy    = mean(yes == classified),
    precision   = sum(yes == 1 & classified == 1) / sum(classified == 1),
    recall      = sum(yes == 1 & classified == 1) / sum(yes == 1),
    specificity = sum(yes == 0 & classified == 0) / sum(yes == 0),
    f1          = 2 * precision * recall / (precision + recall)
  )
# A tibble: 1 × 5
  accuracy precision recall specificity    f1
     <dbl>     <dbl>  <dbl>       <dbl> <dbl>
1    0.922     0.941  0.915       0.931 0.928

On this close vote, all five tell the same story. They part ways on a lopsided vote, where the rare no votes are the interesting class. Call them the positives: a model that predicts yes for everybody matches the PMC in accuracy, but its recall is 0, and its precision and F1 are undefined. So precision, recall and F1 depend on which class we call positive. Switch yes and no, and they change. Accuracy stays the same.

Expected vs. predicted values

Quantity of interest (estimand): the expected vote of an MEP with given values, . A predicted value is a quantity of interest, but not an estimand in this sense: it aims at a single MEP’s vote.

As in Weeks 7 and 8, the model has a systematic and a random part. For a binary outcome, the terms are:

  • Expected value: . Since the mean of a 0/1 variable is the probability of a 1, expected values in a binary model are also called predicted probabilities. They lie between 0 and 1.
  • Predicted value: a single vote drawn from the model, . It is 0 or 1.

So a predicted probability is an expected value, not a predicted value.

augment() returns the linear predictor by default. type.predict = "response" applies and gives the expected values. A draw from the Bernoulli gives the predicted values:

The expected values follow the S-curve, with small differences by age. The predicted values are zeros and ones, like the observed votes.

The two kinds of uncertainty stay the same:

  • Estimation uncertainty: we don’t know the true . Expected values and first differences carry only this one.
  • Fundamental uncertainty: even with the true , one MEP’s vote is a random draw. Unlike with the Normal, no separate is needed: the Bernoulli’s variance follows from . Predicted values carry both.

The bands are narrow at the edges and wide in the middle, the reverse of the linear model. Near 0 and 1 the S-curve is flat, so uncertain coefficients barely move the probability.

Over most of the scale, the two bands overlap. That alone doesn’t tell us whether age makes a difference. Two overlapping intervals can still belong to a difference whose own interval excludes zero, because both expected values come from the same bootstrap refits and move together. The question needs its own quantity, the first difference with its own interval, in the lower panel.

Here, old MEPs are more likely to vote yes, by up to 20 percentage points around position 4.5. But the interval includes zero everywhere, if only just: the data can’t rule out that age makes no difference at all. Its sign comes down to the age coefficient, so the lower bound sits near zero along the whole scale.

Predicted values

Quantity of interest: the vote of a single new MEP in the scenario. marginaleffects has no predicted values, but the bootstrap draws of the expected values give them: each draw feeds one Bernoulli draw.

boot_pvs <- ev_draws |>
  mutate(predicted = rbinom(n(), size = 1, prob = draw))

boot_pvs |>
  count(quantity, predicted)
# A tibble: 4 × 3

1 EV, EPP           0   827
2 EV, EPP           1   173
3 EV, Renew         0   213

Here the Normal case’s interval doesn’t carry over. A 95% interval of a 0/1 draw is just “0 to 1”. What the predicted values tell us is how often each vote occurs, and that share is again the expected value:

boot_pvs |>
  group_by(quantity) |>
  summarize(
    share_yes = mean(predicted),
    expected  = mean(draw)
  )
# A tibble: 2 × 3
  quantity  share_yes expected
  <chr>         <dbl>    <dbl>
1 EV, EPP       0.173    0.169
2 EV, Renew     0.787    0.796

We can be quite sure about the probability, and still unsure about a single MEP’s vote: this is the fundamental uncertainty of a Bernoulli.

Concluding remarks

A 0/1 outcome is out of reach for OLS, and a plain Bernoulli can’t use the data. A GLM joins them: the linear predictor stays, and a response function turns it into a probability for the Bernoulli. Expected values are predicted probabilities, predicted values are 0/1 draws. The bootstrap and the quantities of interest work as before, with added. Next week: the same framework for counts.
