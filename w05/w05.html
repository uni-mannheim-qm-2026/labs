Statistical control by hand

How much of the turnout slope is left once we hold the region constant? Following the lecture, we purge east out of both variables and then regress what’s left on each other, in three steps.

Venn diagrams help to follow along. Each circle stands for how much one variable differs from county to county. Where two circles overlap, knowing one variable helps to predict the other: the bigger the overlap, the better the prediction. Whatever lies outside all other circles, none of them can predict:

Choosing control variables

Above, we held east constant as if it obviously belonged in the model. Whether a variable belongs in a model is a causal question, and the data alone can’t answer it. We switch to a small, well-defined example to see why.

What we know about how the office works: it allocates booths by the number of eligible voters. Shortly after noon, it sends an observer to every station that reports a queue of more than 12 minutes, and to every large station, meaning one with 6 booths. Observers only watch and take notes.

Causal graphs

A directed acyclic graph (DAG) draws our assumptions about what causes what: each node is a variable, each arrow a direct causal effect, and no chain of arrows leads back to where it started. Any sequence of arrows connecting and , whichever way they point, is a path. A path that starts with an arrow into is a backdoor path: it creates an association between and that isn’t ’s effect.

Two building blocks decide whether a path is open:

  • A confounder sits on a fork, . The path is open, and controlling for closes it.
  • A collider sits where two arrows meet, . The path is closed, and controlling for opens it.

With nothing controlled for, the confounder’s backdoor path is open (pink) and biases the estimate of ’s effect on :

The collider’s path stays closed (grey) as long as we leave out of the model:

To estimate the effect of on , we need a set of controls that closes every backdoor path without opening a new one, an adjustment set.

Drawing DAGs with dagitty

dagitty reads a DAG written in its own model code: one line per node (with optional attributes in brackets), one line per arrow. Each DAG’s model code below also works in the browser: paste the text between dagitty(' and ') into the “Model code” box at dagitty.net to move nodes around and click through controls interactively.

To draw the same DAGs here, include/plot_dag.R provides plot_dag(), which uses dagitty.net’s styles: green with a triangle for the exposure, blue with a bar for the outcome, white for what we control for, and light grey for what we don’t observe. Arrows on the causal path are green, and arrows on an open path that biases the estimate are pink. It takes the DAG (what we control for is marked [adjusted] in its model code) and, optionally, readable node labels; without them, it shows the variable names:

source("include/plot_dag.R")

  "booths",        "Booths",
  "wait",          "Waiting time",
  "eligible",      "Eligible voters",
  "observer",      "Observer visit",

Two competing DAGs

Usual turnout is how many of a district’s eligible voters habitually go to vote. The office knows it from experience, but it is not recorded anywhere. Most arrows are uncontroversial:

  • : the office allocates booths by the number of eligible voters.
  • : more eligible voters means more people in the queue.
  • : each booth processes voters in parallel, so more booths shorten the queue. This is the effect we want.
  • : where people usually vote a lot, more of the eligible voters show up today, and the queue gets longer.
  • : the same voting habit produced last election’s turnout.
  • : every large station gets an observer.
  • : every station reporting a long queue gets an observer.

The disputed arrow is . In DAG A, the office follows a strict booths-per-voter rule, and the arrow doesn’t exist:

dag_a <- dagitty('dag {
  booths        [exposure, pos="0,0"]
  wait          [outcome, pos="3,0"]
  eligible      [pos="1.5,-1.7"]
  observer      [pos="1.5,-0.75"]
  usual_turnout [latent, pos="1.5,1.2"]
  last_turnout  [pos="3,1.6"]
  eligible      -> booths
  eligible      -> wait
  booths        -> wait
  booths        -> observer
  wait          -> observer
  usual_turnout -> wait
  usual_turnout -> last_turnout
}')
plot_dag(dag_a, labels = node_labels)

In DAG B, officials know their districts and add booths where turnout is usually high:

dag_b <- dagitty('dag {
  booths        [exposure, pos="0,0"]
  wait          [outcome, pos="3,0"]
  eligible      [pos="1.5,-1.7"]
  observer      [pos="1.5,-0.75"]
  usual_turnout [latent, pos="1.5,1.2"]
  last_turnout  [pos="3,1.6"]
  eligible      -> booths
  eligible      -> wait
  booths        -> wait
  booths        -> observer
  wait          -> observer
  usual_turnout -> wait
  usual_turnout -> last_turnout
  usual_turnout -> booths
}')
plot_dag(dag_b, labels = node_labels)

adjustmentSets() lists the minimal adjustment sets among the observed variables. Under DAG A, eligible voters are enough:

adjustmentSets(dag_a)
{ eligible }

Under DAG B, there is none: the backdoor path through usual turnout can only be closed by controlling for usual turnout itself, which we don’t observe:

dag_b |>
  adjustmentSets() |>
  length()
[1] 0

Nothing in the data tells us which DAG is right. It’s a claim about how the election office works, and choosing one is an assumption we have to state and defend. We go with DAG B from here on.

5 model variants

We estimate the effect of booths on waiting time five times, each with a different set of controls. Every variant follows the same pattern: the model, its DAG with the controls marked, dagitty’s verdict, the regression, a plot, and the booth coefficient next to the true effect.

Variant Controls Control types dagitty verdict
1 none two backdoor paths open
2 Elig Elig: confounder one backdoor path still open
3 Elig, T-Usual* Elig: confounder; T-Usual: unobserved confounder, imagined observed valid adjustment set
4 Elig, T-Last Elig: confounder; T-Last: proxy for usual turnout one backdoor path still open
5 Elig, T-Last, Obs Elig: confounder; T-Last: proxy for usual turnout; Obs: collider collider path opened

Elig = eligible voters, T-Usual = usual turnout, T-Last = last turnout, Obs = observer visit. Model names in tables and plots list their controls the same way. * Usual turnout is unobserved in practice: variant 3 is impossible with real data, a thought experiment we can only run because of how the data came about.

In every DAG below, the controls are marked [adjusted] in the model code, so pasting it into dagitty.net reproduces the plot.

Checking adjustment sets in one run

Every variant’s DAG code marks its controls [adjusted]. isAdjustmentSet() checks whether a set we chose is valid, so one rowwise() pass checks all five variants at once:

variant_dags <- tibble(
  variant = names(variant_models),
  dag     = list(dag_v1, dag_v2, dag_v3, dag_v4, dag_v5)
)

variant_dags |>
  rowwise() |>
  mutate(
    controls = str_flatten_comma(adjustedNodes(dag)),
    valid    = isAdjustmentSet(dag, adjustedNodes(dag))
  ) |>
  ungroup() |>
  select(variant, controls, valid)

We didn’t need to try out control sets at all. adjustmentSets() finds the valid ones from the DAG alone: it ignores [adjusted] marks and only needs to know which variables are observed. For the original DAG B, with usual turnout unobserved, it finds none:

In variant 3’s DAG, usual turnout is observed, and adjustmentSets() finds exactly one minimal set:

With type = "all", it lists every valid set, not just the smallest ones:

adjustmentSets(dag_v3, type = "all")

The true effect

The polling stations aren’t real: we simulated them, following DAG B. That’s how we know the true effect, which real data never tells us. The code that generated the data:

p_load(tidyverse)
set.seed(175)
n_districts <- 300

# eligible voters per district
eligible_mean <- 1600
eligible_sd   <- 380
eligible_min  <- 800
eligible_max  <- 2500

# usual turnout (%): the voting habit of the district, known to the office, normally never recorded
turnout_mean       <- 72
turnout_sd         <- 7
turnout_min        <- 52

voters_per_booth  <- 500

booths_min        <- 1
booths_max        <- 6

wait_mean         <- 12

wait_noise        <- 4

# observers go to every station with the most booths and to every long queue

polling_stations <- tibble(
  district      = 1:n_districts,
  eligible      = rnorm(n_districts, eligible_mean, eligible_sd) |>
    pmax(eligible_min) |>
    pmin(eligible_max) |>
    round(),
  usual_turnout = rnorm(n_districts, turnout_mean, turnout_sd) |>
    pmax(turnout_min) |>
    pmin(turnout_max),
  last_turnout  = round(usual_turnout + rnorm(n_districts, 0, last_turnout_noise), 1),
  booths        = (eligible / voters_per_booth +
    (usual_turnout - turnout_mean) / turnout_per_booth +
    rnorm(n_districts, 0, booths_noise)) |>
    round() |>
    pmax(booths_min) |>
    pmin(booths_max),
  wait          = (wait_mean +
    wait_per_eligible * (eligible - eligible_mean) +
    wait_per_turnout * (usual_turnout - turnout_mean) +
    true_effect * (booths - booths_mean) +
    rnorm(n_districts, 0, wait_noise)) |>
    pmax(0) |>
    round(),
  observer      = as.integer(booths == booths_max | wait > observer_wait)
)

  select(-usual_turnout) |>

Depending on what we control for, the same data tell very different stories. Without controls, the estimate even has the wrong sign: booths seem to lengthen the queue. Controlling for eligible voters alone, or adding the observer visit on top of the proxy, recovers only about half of the true effect. The proxy gets to about four fifths, and its CI still covers the true effect. Only the valid adjustment set of variant 3 hits the true effect, and it needed a variable we don’t have.

Concluding remarks

Which variables to control for follows from a causal graph, and the graph is an assumption: here, a single disputed arrow decided whether any adjustment set exists at all. Papers make the same assumptions whenever they “control for” something, usually without drawing them. Some confounders are unobserved; a proxy can narrow the gap they leave, but not close it. Controlling for the wrong variable, like a collider, can make an estimate worse, and no fit statistic warns you. Without a full course in causal inference, writing the DAG down in dagitty and checking its adjustment sets is a minimum. Standard errors and significance come in Week 6.
